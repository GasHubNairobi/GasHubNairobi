ONE-TIME STEPS WHEN YOU HAVE THE VALUES
1. Restart the server (the app creates the tables it needs by itself).
2. Phone prompt works as soon as MPESA_ENV, KEY, SECRET, SHORTCODE, PASSKEY, CALLBACK_BASE_URL and CALLBACK_SECRET are filled.
3. To check typed M-Pesa codes: set MPESA_C2B_ENABLED=true, then run once:  node backend/scripts/register-mpesa-c2b.js

ROUTES (all under /api/payments)
  GET  /mpesa/config                   { enabled, verifyEnabled }  what is switched on
  POST /mpesa/stk-push                 { order_id, phone }         sends the PIN prompt (amount is worked out on the server)
  GET  /mpesa/status                   ?order_id&checkout_request_id   the page polls this
  POST /mpesa/callback/:secret         Safaricom -> us, prompt result
  POST /mpesa/c2b/validation/:secret   Safaricom -> us, paybill/till payments (accept)
  POST /mpesa/c2b/confirmation/:secret Safaricom -> us, paybill/till payments (saved)
  POST /mpesa/verify-code              { order_id, code }          paid | not_found | short | already_used | unavailable
  GET  /bank/config                    GasHub bank details for the customer
  POST /bank/verify                    { order_id, reference }     paid | not_found | short | unavailable

WHAT THE CUSTOMER SEES (customer-checkout.html, pay mode)
  M-Pesa: phone number box -> "Pay" -> prompt on the phone -> success. If it is slow (25 s), fails, or times out, a box appears:
          "Already paid? Enter your M-Pesa code". The code is checked: received -> success; not found / too little / used ->
          "Payment not confirmed" with "Check again" and "Pay again".
  Bank:   GasHub bank details + the order number to use as reference -> customer enters the bank reference -> checked the same way.
  If automatic checking is not switched on yet, the code is sent to GasHub to confirm by hand (the old behaviour) and the
  customer sees "Payment submitted".
